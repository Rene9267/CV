by Antonio Troiano — Architecture & Code

/Introduzione

ActionFlow e' un framework di orchestrazione asincrona e event-driven per Unity, pensato per trasformare flussi di gioco complessi in unita' atomiche e governabili. Nato per eliminare lo "spaghetti code" nei progetti enterprise, trasforma la logica sequenziale in una catena di Actions eseguite da Sections e gestite da un orchestratore centrale (ActionFlowMGR).

Costruito su UniTask per un'async management ad alte prestazioni e zero-allocation, il framework offre un modello di try-catch-BREAK per la crash isolation, un sistema di Blackboard per la comunicazione tra componenti, e DynamicValue<T> per parametri risolvibili a runtime da sorgente locale o blackboard.

"Eliminare il caos nei flussi di gioco complessi, un'Action alla volta."

/Architettura

Il sistema si basa su tre pilastri che formano la "Trinita' del Flusso": un contenitore che gestisce il ciclo di vita, un esecutore che orchestra le azioni, e un'unita' atomica che incarna la singola responsabilita'.

Container

ActionFlowMGR

MonoBehaviour — gestisce Section lifecycle, avanzamento sequenziale e jump overrides

▼
Executor

Section

MonoBehaviour — possiede una List<Action>, esegue con Wait/Forget e crash handling

▼
Atomic

Action

POCO class — single responsibility, serializzata via [SerializeReference], decouplata da Unity

/Componenti_Core

ActionFlowMGR

Il gestore centrale. Validazione sezioni all'Awake, inizializzazione della Blackboard, attivazione della prima Section. Quando una Section completa, il MGR decide se avanzare sequenzialmente o eseguire un jump tramite flow override. Ogni transizione pulisce CTS, unsubscribe e disattiva la sezione precedente.

ActionFlowMGR.cs — Ciclo di Vita

// Awake: valida sections, crea blackboard, disattiva tutto

// Start: avvia la prima section (o la debug section)

// HandleSectionComplete: callback di completamento

// StartNextSection: avanzamento sequenziale o jump

// ExecuteSection: attiva, subscribe, start

// CleanUpCurrentSection: cancel CTS, unsubscribe, disattiva

Section

L'esecutore. Ogni Section possiede una lista di Actions e le esegue in sequenza. Supporta due modalita': Wait (la Section attende il completamento dell'Action prima di proseguire) e Forget (l'Action viene lanciata e la Section prosegue immediatamente). Il crash handler catta le eccezioni e ferma la catena in modo pulito.

Section.cs — ExecuteActionChain

void ExecuteActionChain(CancellationToken ct) {

// foreach action in Actions:

// crea ActionContext

// if ShouldWaitForCompletion → await Execute

// else → fire-and-forget

// catch → log error, BREAK chain

// onComplete → SectionCompleted.Invoke()

}

Action

L'unita' atomica. Classe POCO astratta con un solo metodo: UniTask Execute(ActionContext context). Ogni Action ha una singola responsabilita'. Il flag _waitForCompletion (DynamicBool) controlla se la Section deve attendere. Il metodo virtuale IsInstantaneousAction() nasconde il flag in editor per le azioni sincrone.

/Dati_Comunicazione

FlowBlackboard

ScriptableObject che funge da bus di comunicazione centralizzato. Supporta tipi primitivi (bool, float, int, string), vettori, quaternioni, oggetti generici e ScriptableObjects. Tutti i getter lanciano eccezioni in caso di errore (fail-fast): KeyNotFoundException per chiavi mancanti, InvalidCastException per tipi sbagliati.

FlowBlackboard.cs — API

bool GetBool(string key)

void SetBool(string key, bool value)

float GetFloat(string key)

void SetFloat(string key, float value)

T Get<T>(string key) // generic access

void SetFlowOverride(int sectionIndex) // jump navigation

DynamicValue<T>

Pattern generico per parametri risolvibili a runtime. Ogni Action puo' ricevere valori sia da sorgente Locale (valore hardcoded nell'Inspector) che da Blackboard (letto dinamicamente a runtime). Implementazioni concrete: DynamicFloat, DynamicInt, DynamicBool, DynamicString, DynamicVector3, DynamicQuaternion, DynamicAudioSource, DynamicVideoPlayer, DynamicAnimator, DynamicGameObject, DynamicRenderer, DynamicMaterial e molte altre.

DynamicValue<T> — Pattern

enum DataSource { Local, Blackboard }

abstract T GetBlackboardValue(FlowBlackboard bb, string key)

// Se DataSource == Local → ritorna il valore hardcoded

// Se DataSource == Blackboard → legge da FlowBlackboard

// Tutti i parametri delle Actions usano questo pattern

FlowSignal & GameEvent

Due meccanismi di comunicazione event-driven. FlowSignal e' basato su UniTaskCompletionSource per l'async waiting: puo' essere alzato e atteso con WaitAsync(CancellationToken). GameEvent e' il classico observer pattern con registrazione/rimozione listener, pensato per eventi broadcast (UI update, feedback sonoro, ecc.).

/Pattern_Esempi

Il sistema supporta tre pattern di esecuzione principali, ognuno con un contratto di eccezione specifico:

Root Executor

try-catch-BREAK. La Section catta l'eccezione e ferma la catena. Crash isolation.

Nested Executor

try-catch-THROW. Act_Group e Act_Parallel propagano l'eccezione verso l'alto.

Isolated Executor

try-finally. Act_ExecutePreset usa un blackboard locale isolato con cleanup garantito.

Code-First API — Esempio

// Flusso definito da codice, non da Inspector

ActionFlowCodeFirst.Template("GameLoop",

Act_WaitForSignal(startSignal)

.Then(Act_LoadScene("Level01"))

.Wait(Act_FadeAudio(music, 2f))

.Group(

Act_PlayVideo(cutscene),

Act_PlayAudio(sfx)

)

.Parallel(enemies.Select(e => e.Attack()))

);

// Fluent API: .Then() .Wait() .Group() .Parallel() .Race() .If()

/Note

ActionFlow e' nato come soluzione a un problema reale: i flussi di gioco enterprise in Unity (training VR, simulazioni industriali) tendevano a diventare ingestibili con MonoBehaviour tradizionali. La separazione in Actions atomiche con comunicazione via Blackboard ha reso il codice testabile, manutenibile e comprensibile anche per team non tecnici.

Il pacchetto e' distribuito come 3 UPM packages separati: Core (base), HurricaneVR (integrazione VR), AdvancedDissolve (effetti dissolve). Ogni package e' installabile indipendente via Git URL.

Questa documentazione copre il Core package. Le integrazioni HurricaneVR e AdvancedDissolve saranno documentate separatamente.
